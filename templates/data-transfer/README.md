# ورود و خروج کاتالوگ

هر فایل JSON یک آرایه از رکوردهای یک بخش است. تصاویر را ابتدا در «رسانه‌ها» بارگذاری کنید و با نام دقیق فایل ارجاع دهید. تصویر خالی، حذف‌شده از ورودی یا `null` مجاز است.

ترتیب ورود:

1. `brands.json`
2. `categories.json` — والدها پیش از فرزندان
3. `attributes.json` — بخش «ویژگی‌ها»
4. `attribute-options.json` — بخش «گزینه‌های ویژگی»
5. `products.json`
6. `variants.json` — فقط مدل‌های واقعی و دستی

در `categories.json`، مقدار `showOnStorefront: true` دسته را در صفحه اصلی و فهرست فروشگاه نمایش می‌دهد. حداکثر شش دسته می‌توانند انتخاب شوند و `sortOrder` ترتیب نمایش آن‌ها را مشخص می‌کند؛ سایر دسته‌ها و مسیر مستقیم آن‌ها حذف نمی‌شوند.

برای محصول ساده، `productType: "simple"`، بدون `variantAttributes` و بدون مدل ثبت کنید. برای محصول متغیر از `productType: "variable"` استفاده کنید. هر ردیف `attributes` شامل `attribute`، `allowedOptions` و در صورت نیاز `required` است. فقط ویژگی‌های تخصیص‌یافته می‌توانند در `variantAttributes` باشند.

**ویژگی‌ها به‌صورت خودکار مدل ایجاد نمی‌کنند.** پارچه و رنگ می‌توانند انتخاب مشتری باشند و به تعداد مدل‌ها اضافه نکنند. هر مدل باید دقیقاً یک گزینه از هر ویژگی سازنده مدل داشته باشد. کد SKU و ترکیب گزینه‌ها باید یکتا باشند.

| بخش / ارتباط | کلید قابل‌حمل |
| --- | --- |
| محصول، برند، دسته‌بندی، مطلب، پروژه | `slug` |
| ویژگی | `name` |
| گزینه ویژگی | `value` (یکتای سراسری) |
| مدل محصول | `nilperCode` |
| رسانه | `filename` |

نام‌های داخلی افزونه برای بخش ویژگی و گزینه، `variantTypes` و `variantOptions` هستند؛ `variantType` در فایل گزینه به کلید ویژگی اشاره دارد. این‌ها یک سیستم ویژگی مشترک‌اند. نام فایل‌ها و عنوان‌های مدیریت از اصطلاحات ساده استفاده می‌کنند.

گزینه‌ها از `label`، `code`، `groupLabel` (نام پالت یا خانواده)، `image`، `colorHex`، `active` و `sortOrder` پشتیبانی می‌کنند. مثال `VR-A01` با `groupLabel: "Verona Palette"` به مجموعه جداگانه‌ای نیاز ندارد.

قیمت فعال محصول مبنای مدل‌هاست. در مدل، `priceInTMNEnabled: false` یعنی استفاده از قیمت محصول؛ `true` همراه با `priceInTMN` قیمت اختصاصی است. ارسال، موجودی و تصویر خالی مدل از محصول به ارث می‌رسند. در اندازه‌ها و مشخصات، کلید و ترتیب خودکارند؛ کلیدهای موجود در خروجی برای به‌روزرسانی حفظ می‌شوند.

ورود و خروج فقط برای مدیر و از منوی فهرست هر بخش انجام می‌شود. روش‌های ایجاد، به‌روزرسانی و ایجاد/به‌روزرسانی موجودند؛ کلید تطبیق پیش‌فرض با کلید پایدار جدول جایگزین می‌شود. فایل‌های `posts.json`، `projects.json` و `blog-categories.json` مستقل از کاتالوگ باقی می‌مانند.

کارها در Payload Jobs اجرا می‌شوند. سابقه و فایل انتقال پس از هفت روز حذف می‌شوند؛ محتوای واردشده حذف نمی‌شود.
